Project 3 — Linux Boot Steps

Reference sheet — readable from Ubuntu's own browser once you're connected to WiFi
Goal of this page: get the iPad from DFU mode into a "PongoOS" shell for the first time, using the real palera1n tool on real (non-virtual) Linux. That's the only thing this covers. Uploading the kernel/module is a separate step after this is confirmed working.

1 Boot into the USB

  1. Start menu → Power → Shut down (full shutdown, not restart)
  2. Press the power button
  3. The instant it powers on, tap Esc repeatedly (HP Startup Menu)
  4. Press F9 for Boot Device Options
  5. Arrow keys → select the USB drive → Enter
  6. At Ubuntu's screen, choose "Try Ubuntu" — never "Install Ubuntu"

2 Connect to WiFi

  1. Click the network icon, top-right of the screen
  2. Select your WiFi network, enter the password, connect

3 Open a Terminal

  1. Click "Activities" (top-left) or the search icon
  2. Type terminal, open it

4 Download and verify the exact tool

Paste each line, press Enter after each:

cd ~/Desktop
wget https://github.com/palera1n/palera1n/releases/download/v2.0.0-beta.9/palera1n-linux-x86_64
chmod +x palera1n-linux-x86_64
sha256sum palera1n-linux-x86_64

Output must match exactly:

5b6dec3a7ee15b14e989466a098d02edeb8455070009ffaa228caf2b3298dbd8

If it does not match exactly — stop and report back before continuing.

5 iPad into DFU mode

  1. Plug the iPad into the laptop via USB
  2. Hold Power + Home together for exactly 8 seconds
  3. At 8 seconds, release Power only, keep holding Home for 5 more seconds
  4. Screen must stay completely black the whole time. Apple logo appearing = failed, just retry.

6 Safe check (no changes made)

./palera1n-linux-x86_64 -I

Expect to see:

Mode: DFU
ProductType: iPad5,3
DisplayName: iPad Air 2 (WiFi)

If it hangs or shows nothing, the iPad dropped out of DFU — redo step 5.

7 The real step

./palera1n-linux-x86_64 -p

Then immediately go to Section 9 below and follow whichever branch matches what you see. Don't guess — find your exact situation in the list.

9 Troubleshooting — find what you're seeing

A. First, always run this one check:

lsusb

Look through the list it prints for a line containing 05ac (that's Apple's ID). Then go to the branch below that matches:

B. lsusb shows NOTHING with 05ac in it at all

The iPad isn't connected or isn't in DFU mode. Do this:

  1. Check the USB cable is firmly plugged in at both ends
  2. Try a different USB port on the laptop if one is free
  3. Redo DFU entry exactly: Power+Home 8 sec together → release Power only → hold Home 5 more sec → screen must stay pure black the entire time
  4. Run lsusb again after each attempt
  5. Repeat up to 5 times. If still nothing after 5 clean attempts, stop and note that — it's worth reporting, not normal.

C. lsusb DOES show an Apple device with ID 05ac:1227

Good — DFU mode is real and Linux sees it. Now run:

./palera1n-linux-x86_64 -I

Expected good output includes Mode: DFU and ProductType: iPad5,3.

  • If that text appears: go straight to branch D below.
  • If it hangs with no output, or only shows the startup banner and the usbmuxd warning with nothing after: press Ctrl+C to stop it, then try running it with elevated permissions instead: 
    sudo ./palera1n-linux-x86_64 -I
    (If it asks for a password and you don't have one set, just press Enter — the default Ubuntu Live session often has no password.)
  • If that still shows nothing after ~15 seconds: unplug the USB cable, wait 2 seconds, plug back in, redo DFU entry (step 5), and try the -I check again from the top of branch C. Repeat up to 3 times.

D. -I correctly shows Mode: DFU / iPad5,3 — now run the real exploit:

./palera1n-linux-x86_64 -p

(add sudo in front too if step C needed it: sudo ./palera1n-linux-x86_64 -p)

  • If it prints an error/"Failed"/"Unable to perform checkm8" and stops: this is a known, normal thing — this exploit is a timing trick and often needs several tries. Unplug the cable, wait 2 sec, replug, redo DFU entry (step 5), run -p again. Repeat up to 6-7 times before treating it as a real problem — this is genuinely expected, not a sign of failure.
  • If it hangs at "Waiting for devices" for more than ~30 seconds without progressing: same fix — Ctrl+C, unplug/replug, redo DFU, try again.
  • If the exact same specific error text repeats identically after 6-7 clean attempts (same wording every time, not just "still waiting"): stop, write down or screenshot the exact error text, and that's what to bring back — don't keep looping past that point.
  • If you see a wall of checkra1n/Pongo-style text and it ends on a new prompt that just sits there waiting for input: that's success. Stop. Don't type anything else into it.

E. Once you have an outcome (success OR a repeating identical error after 6-7 tries)

Screenshot or photograph exactly what the terminal shows. Boot back to Windows (top-right power icon → Restart, remove the USB when prompted). Come back to the same chat and show what you got — include which branch (B/C/D) you ended up on, and how many tries it took.
