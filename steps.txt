PROJECT 3 — STEPS TO RUN INSIDE THE UBUNTU USB (do these in order)
================================================================================
GOAL OF THIS SHEET: get the iPad from DFU mode into a "PongoOS" shell for the
first time, using the real palera1n tool on real (non-virtual) Linux. That is
the ONLY thing this sheet does. Uploading our own kernel/module comes AFTER,
in a separate step, once this part is confirmed working.

--------------------------------------------------------------------------------
PART 0 — BEFORE YOU RESTART THE LAPTOP
--------------------------------------------------------------------------------
- Make sure the Ubuntu USB drive is plugged into the laptop.
- Have the iPad nearby (not necessarily plugged in yet).
- Know your WiFi password (Ubuntu will need to connect to the internet once).

--------------------------------------------------------------------------------
PART 1 — BOOT INTO THE USB DRIVE
--------------------------------------------------------------------------------
1. Click Start -> Power -> Shut down (a full shutdown, not restart).
2. Press the power button to turn it back on.
3. The instant it powers on, start tapping the Esc key repeatedly.
   (This is specific to HP laptops like yours — Esc opens the "Startup Menu".)
4. When the Startup Menu appears, press F9. This opens "Boot Device Options".
5. Use the arrow keys to highlight the USB drive in the list (it will mention
   "USB" in its name), then press Enter.
6. Ubuntu's boot screen appears. Use arrow keys if needed and select
   "Try Ubuntu" (NOT "Install Ubuntu"). Press Enter.
7. Wait for the Ubuntu desktop to load (can take 1-2 minutes).

--------------------------------------------------------------------------------
PART 2 — CONNECT TO WIFI
--------------------------------------------------------------------------------
1. Look at the top-right corner of the screen for a network/WiFi icon.
2. Click it, select your WiFi network name from the list.
3. Type your WiFi password, click Connect.
4. Wait until it shows as connected.

--------------------------------------------------------------------------------
PART 3 — OPEN A TERMINAL
--------------------------------------------------------------------------------
1. Look for a "Activities" button (top-left) or a search icon.
2. Type: terminal
3. Click the "Terminal" application that appears. A black window with text
   opens — this is where you will type all the commands below.

--------------------------------------------------------------------------------
PART 4 — DOWNLOAD AND VERIFY THE EXACT TOOL (copy-paste each line, press Enter)
--------------------------------------------------------------------------------
Type or paste this first line, press Enter:

    cd ~/Desktop

Then this line, press Enter (this downloads the exact file we already tested):

    wget https://github.com/palera1n/palera1n/releases/download/v2.0.0-beta.9/palera1n-linux-x86_64

Wait for it to finish (shows a progress bar, file is about 4.5 MB, should be
quick). Then make it runnable:

    chmod +x palera1n-linux-x86_64

Now verify it is EXACTLY the same file we already tested (very important —
do not skip this):

    sha256sum palera1n-linux-x86_64

The output MUST match exactly (case doesn't matter):

    5b6dec3a7ee15b14e989466a098d02edeb8455070009ffaa228caf2b3298dbd8

If it does NOT match exactly, STOP and tell me — do not proceed.

--------------------------------------------------------------------------------
PART 5 — CONNECT THE IPAD AND ENTER DFU MODE
--------------------------------------------------------------------------------
1. Plug the iPad into the laptop with a USB cable (any free port now — this
   is real hardware, not the shared-port juggling from before).
2. Put it into DFU mode, same as earlier:
   - Hold Power + Home together for exactly 8 seconds.
   - At 8 seconds, release Power only, keep holding Home for 5 more seconds.
   - Screen must stay COMPLETELY BLACK the whole time. If the Apple logo
     appears at any point, it failed — just try again from step 2.

--------------------------------------------------------------------------------
PART 6 — SAFE CHECK (does not touch anything, just confirms detection)
--------------------------------------------------------------------------------
In the terminal, type:

    ./palera1n-linux-x86_64 -I

Expected output includes lines like:

    Mode: DFU
    ProductType: iPad5,3
    DisplayName: iPad Air 2 (WiFi)

If you see that, we're good — continue. If it hangs or shows nothing, the
iPad probably isn't in DFU mode anymore — redo Part 5.

--------------------------------------------------------------------------------
PART 7 — THE REAL STEP: RUN THE EXPLOIT
--------------------------------------------------------------------------------
Type:

    ./palera1n-linux-x86_64 -p

Then immediately go to PART 9 below and find the branch that matches what
you see. Don't guess — find your exact situation in the list.

--------------------------------------------------------------------------------
PART 9 — TROUBLESHOOTING — FIND WHAT YOU'RE SEEING
--------------------------------------------------------------------------------

A. FIRST, ALWAYS RUN THIS ONE CHECK:

    lsusb

Look through the printed list for a line containing "05ac" (Apple's ID).
Then go to the branch below that matches.

B. lsusb SHOWS NOTHING WITH 05ac IN IT AT ALL
   The iPad isn't connected or isn't in DFU mode. Do this:
   1. Check the USB cable is firmly plugged in at both ends
   2. Try a DIFFERENT USB port on the laptop if one is free
   3. Redo DFU entry exactly: Power+Home 8 sec together -> release Power
      only -> hold Home 5 more sec -> screen must stay pure black the
      entire time
   4. Run "lsusb" again after each attempt
   5. Repeat up to 5 times. If still nothing after 5 clean attempts, stop
      and note that -- it's worth reporting, not normal.

C. lsusb DOES SHOW AN APPLE DEVICE WITH ID 05ac:1227
   Good -- DFU mode is real and Linux sees it. Now run:

       ./palera1n-linux-x86_64 -I

   Expected good output includes "Mode: DFU" and "ProductType: iPad5,3".
   - If that text appears: go straight to branch D below.
   - If it hangs with no output, or only shows the startup banner and the
     usbmuxd warning with nothing after: press Ctrl+C to stop it, then try
     with elevated permissions instead:

       sudo ./palera1n-linux-x86_64 -I

     (If it asks for a password and you don't have one set, just press
     Enter -- the default Ubuntu Live session often has no password.)
   - If that still shows nothing after ~15 seconds: unplug the USB cable,
     wait 2 seconds, plug back in, redo DFU entry (Part 5), and try the
     -I check again from the top of branch C. Repeat up to 3 times.

D. -I CORRECTLY SHOWS Mode: DFU / iPad5,3 -- NOW RUN THE REAL EXPLOIT:

       ./palera1n-linux-x86_64 -p

   (add sudo in front too if branch C needed it:
    sudo ./palera1n-linux-x86_64 -p)

   - If it prints an error and stops BEFORE ever showing "Checkmate!":
     unplug the cable, wait 2 sec, replug, redo DFU entry (Part 5), run
     -p again.
   - If it shows "Checkmate!" and then "Timed out waiting for download
     mode": the exploit itself is WORKING -- that's the hard part done.
     Go straight to PART 10 below, which is entirely about fixing exactly
     this.
   - If you see a wall of checkra1n/Pongo-style text ending on a new
     prompt that just sits there waiting for input: THAT IS SUCCESS.
     Stop. Don't type anything else into it.

E. ONCE YOU HAVE A REAL OUTCOME (success, or you've worked all the way
   through PART 10 without success):
   Screenshot or photograph exactly what the terminal shows. Boot back to
   Windows (top-right power icon -> Restart, remove the USB when prompted).
   Come back to the same chat and show what you got -- include which
   branch you ended up on, and roughly how many tries it took.

--------------------------------------------------------------------------------
PART 10 — FIXING "Checkmate!" then "Timed out waiting for download mode"
--------------------------------------------------------------------------------
This exact message means the exploit already worked -- you're past the hard
part. This specific error is common and documented; here is everything known
to help it, worth doing ALL TOGETHER, not one at a time, since tonight's goal
is getting it working, not isolating which change mattered:

DO ALL OF THESE BEFORE YOUR NEXT BATCH OF ATTEMPTS:
   1. Unplug the laptop's charger -- run on battery only. AC power noise is
      a documented cause of exactly this failure on some laptops.
   2. Use a different physical USB port if the laptop has more than one
      free. USB 3.0 ports (often blue inside) are more likely to cause
      this than USB 2.0 ones -- prefer a USB 2.0 port if you can identify
      one.
   3. Make sure there is no USB hub, dock, or extension cable between the
      iPad and the laptop -- plug directly into the laptop's own port.
   4. If you have a second USB-A cable available (even an old one), try
      swapping it -- shorter, simpler cables tend to be more reliable
      here than long or "fast charging" ones.
   5. Wait a full 5-10 seconds after unplugging the iPad before plugging
      it back in (longer than before).

THEN RETRY GENEROUSLY -- this can genuinely take many attempts:
   With the changes above in place: redo DFU entry (Part 5) -> run the
   safe check (-I, confirm Mode: DFU) -> run
   "sudo ./palera1n-linux-x86_64 -p". If it fails the same way, unplug/
   replug (5-10 sec wait), redo DFU, try again.

   GIVE THIS AT LEAST 15-20 ATTEMPTS before concluding it's not working --
   reaching "Checkmate!" reliably (which you already have) means the
   hardware/exploit combination genuinely works, and this specific
   reconnect step is known to sometimes just need persistence. Don't stop
   at attempt 5 or 6 and assume it's hopeless.

OPTIONAL EXTRA THINGS TO CHECK if 15-20 tries with the above still fail:
   - If the iPad has a passcode set: reported to interfere with this exact
     step on some devices. If easy to do, temporarily turning off the
     passcode (Settings -> Face/Touch ID & Passcode -> Turn Passcode Off)
     before starting DFU mode is worth trying.
   - Full fresh restart of the Ubuntu USB itself (not just the iPad) --
     cold shutdown, boot back into the USB, in case something in the
     current session's USB state is stuck.
   - Get more detail for next time with extra logging:

       sudo ./palera1n-linux-x86_64 -v -v -p

     This won't fix it alone, but if you do need to come back and ask,
     this output is far more useful to look at than the plain version.

If after genuinely working through all of this (15-20+ tries, power/port/
cable changes, optionally the passcode check) it still fails the exact same
way every time -- that's the real point to stop and come back, ideally with
the -v -v output. That's a real, worth-reporting result, not giving up
